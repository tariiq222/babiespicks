# الاسترجاع

المخطط الجديد إضافي؛ إعادة صورة أقدم لا تزيل الأعمدة أو البيانات. مع ذلك، تشغيل NestJS القديم مباشرة ليس رجوعًا آمنًا: بعض detail queries القديمة لا تحرس النشر، وقد تكشف مسودات. لا تبدأ ناشريه/كرونه أو توصلهم لقاعدة النسخة الجديدة.

## قبل أي كتابة جديدة بعد التحويل

يمكن إعادة التوجيه إلى واجهة قديمة ثبت أنها تحرس حالات النشر، أو وضع الموقع في صيانة مع إبقاء قاعدة البيانات والوسائط سليمتين. إذا لم توجد صورة قديمة آمنة، المسار هو الصيانة وإصلاح النسخة المبسطة، لا فتح الخدمة القديمة دون مراجعة.

## بعد الكتابات الجديدة

1. أوقف الكتابة والروتين الخارجي ومهام النشر. احتفظ بقراءات الموقع إن كانت آمنة.
2. خذ نسخة حديثة من القاعدة والوسائط وسجل فترة التحويل. لا تستعد نسخة أقدم فوقها؛ ذلك يفقد منتجات/منشورات/نقرات جديدة.
3. ارجع إلى آخر صورة مبسطة مختبرة متوافقة مع نفس المخطط. احتفظ بالبيانات الجديدة، ثم اختبر الجاهزية والقراءة والتحويل والنشر/السحب بإذن محدد.
4. عند أول انتقال قبل توفر صورة مبسطة سابقة: ضع صيانة مؤقتة واعمل forward-fix. الرجوع للقديم يحتاج أولًا إصلاح حراس النشر ونقل فرق الكتابات والتحقق منه على نسخة معزولة.
5. راجع أي نشر اجتماعي غامض قبل إعادة المحاولة؛ لا تُعد استدعاء جهة خارجية قد تكون نفذت الطلب بالفعل.

تجربة الاستعادة المحلية تعيد dump لقاعدة اختبار إلى قاعدة اختبار ثانية وتطابق الهوّيات والأعداد. هذه تثبت النسخ والاستعادة، ولا تُعد تجربة رجوع لإنتاج لم يُنقل بعد. تجربة التحويل والرجوع الفعلية تظل شرطًا قبل قطع الإنتاج.
