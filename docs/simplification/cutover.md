# الانتقال إلى النسخة المبسّطة

## الحالة

التنفيذ المحلي لا يعني أن الإنتاج انتقل. فحص HTTPS للنطاقين وSSH للمضيف المسجل انتهى بمهلة اتصال في 21 أكتوبر 2026؛ لم تُقرأ قاعدة الإنتاج ولم تُغيّر. لا تفترض أنها فارغة لأن الموقع متوقف. تُراجع منصة الاستضافة والعناوين والـwebhook والصور الفعلية عند توفر الوصول، قبل تشغيل أو نشر أي خدمة.

## التحضير

1. تحقق من الفرع/الرأس ومنح النشر ومصدر إعدادات الاستضافة؛ لا ترفع تغييرات التشغيل إلى main بلا تفويض، فقد يشغل webhook قديمًا.
2. انسخ قاعدة البيانات والوسائط إلى مخزن آمن، واختبر استعادة النسخة على قاعدة معزولة. لا تخزن تفريغ الإنتاج أو الأسرار في المستودع.
3. طابق schema الفعلي مع `packages/db/prisma/schema.prisma` وتاريخ `_prisma_migrations`. ملف SQL القديم `0030_phase3_review_workspace.sql` كان خارج مجلدات Prisma وبأسماء أعمدة مختلفة؛ لا تشغله. الترحيل الجديد إضافي ويتوقف إن اصطدم بشكل قديم غير متوافق؛ تُكتب معالجة تحويل منفصلة من أدلة القاعدة، ولا reset أو drop.
4. احصر المهام الاجتماعية والمؤجلة والنشرات والاتصالات الخارجية. يحتفظ النقل بهذه السجلات دون تنفيذها. اختر ما يُلغى أو يُنقل إلى مشغّل خارجي؛ لا تشغيل مشغّلين على المحتوى نفسه.
5. جهز أسرار MCP مستقلة، ومضيف HTTPS مستقل، ونسخة واحدة من MCP، وقرص الوسائط الدائم. `ENABLE_MCP_PUBLISH=false` حتى اختبار التفويض مع المالك.

## تجربة النقل ثم الانتقال

نفّذ أولًا على نسخة معزولة. أوامر الأدوات تتلقى DATABASE_URL من بيئة آمنة؛ لا تلصقه في السجلات.

```sh
pnpm db:generate
pnpm db:deploy
pnpm verify:migration capture /secure/location/before.json --legacy
pnpm migrate:legacy
# مراجعة التعارضات، ونسخة قابلة للاستعادة، وتوقف جميع الكتّاب والناشرين القدماء أولًا:
pnpm migrate:legacy --apply --confirm-writers-stopped --database-name=EXACT_DATABASE_NAME
pnpm verify:migration verify /secure/location/before.json
```

التحقق يفشل إذا فقدت الهوّيات أو الروابط أو النقرات أو تاريخ الأسعار أو اختفى محتوى كان منشورًا. تقرير النقل لا يحتوي نصوصًا أو عناوين بريد. اختلاف isPublished/status يعتمد الظهور العام القديم ويُدرج في التقرير؛ تعارض slug عرض مع محتوى آخر يمنع النقل حتى الحسم. النقل المتكرر لا يعيد نشر عنصر أُرشف ولا ينشر مسودات أنشأها MCP.

شغّل صور الويب وMCP المراجعة، ثم وجّه النطاق الرئيسي وروابط `/go` على مضيف API القديم إلى الويب الجديد. إن وُجد مستهلك API خارجي آخر، وفر له عقد توافق أو انتقالًا مقبولًا قبل إيقافه. اختبر صفحات عامة وصورًا وأسعارًا ونقرات على عناصر معروفة، وافحص المخطط والبيانات المنظمة واللغات والسحب من النشر. اختبار كتابة إنتاجي يتطلب عنصرًا مقصودًا وموافقة المالك، وليس نشر مقال تجريبي للعامة.

متغيرات Compose الداخلية: `WEB_REVALIDATE_ALLOW_INTERNAL_HTTP=true` يسمح فقط بعنوان خدمة `http://web:3000/api/revalidate`. هذا الاستثناء لا يسمح بعنوان OAuth غير آمن. منفذ MCP الافتراضي8765، والويب3000.

## بعد الانتقال

راقب سبعة أيام مقترحة تشمل الروتين الخارجي والنسخ الاحتياطي والروابط القديمة والسحب من النشر. احتفظ بجداول الإرث بلا كتّاب مدة30 يومًا مقترحة؛ إسقاط الجداول أو حذف النسخ قرار منفصل. لا تُعد تشغيل خدمات النظام القديم المسترجعة من Git عند إعادة تشغيل المضيف.
